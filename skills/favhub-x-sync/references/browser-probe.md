# X 被动拦截：扩展做什么，Agent 不做什么

X 的 GraphQL 接口依赖请求头鉴权，因此无法由页面自行重放请求。唯一可行的读取
方式是**被动拦截**——只记录 X 自己发出的请求的响应正文。

**这件事完全由 FavHub 浏览器扩展完成，Agent 不参与。** 本文档描述扩展的行为，
以便 Agent 如实向用户解释正在发生什么，而不是一份操作指南。

## 扩展的行为

1. 会话被认领后，扩展才向页面注入钩子，挂钩 `fetch`/`XMLHttpRequest`，
   只记录 URL 匹配 `/i/api/graphql/*/Bookmarks` 的**响应正文**。
   在 FavHub 确认存在待采集会话之前，不缓存也不复制任何东西。
2. 钩子必须早于页面第一次书签请求装好，否则最新的一页会被漏掉。为此扩展在
   认领成功后重载一次标签页——第二次加载时会话已在内存中，装钩子只需几十毫秒。
3. 滚动即分页：页面自身发出的每页请求被钩子记录，扩展按收据节奏推进滚动。
4. 响应正文经原生消息通道交给 FavHub，由纯解析器（`favhub.x_parsers`）解析。

## 安全边界

- 决不读取 `document.cookie`；决不复制或构造 Authorization/Bearer/csrf/ct0
  等鉴权头；决不主动发起 X 请求。被动的含义就是"只看，不问"。
- 扩展在 X 上的请求允许清单是**空的**：X 是被动采集平台，它永远不会让页面
  代为发起任何请求。
- 拦截不可用时停止并报告 `page_changed`，决不回退到 DOM 抓取。

## 需要读取的响应形状

冻结样例见仓库 `tests/fixtures/x/`；实际解析一律交给 FavHub 纯解析器，
关键契约（作者位置、note_tweet 长文、可选 alt、tombstone、cursor 分页）
记录在 `scripts/probe_x_contract.md`。

## 脱敏规则

- 只提交响应**正文**中的业务字段；不得附带请求头、响应头或任何会话凭证。
- 日志与进度报告只写：计数、稳定错误码、推文 ID；决不粘贴原始响应全文。
- 公开作者信息（名称、handle）可以保留；观看者自身身份信息不得写入任何
  条目或日志。
- 鉴权错误响应是 `login_required` 信号，决不当作空列表处理。
